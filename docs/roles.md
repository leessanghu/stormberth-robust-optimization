# 역할 분담

4명 / 약 4주 (2026-11-19 ~ 12월 중순).

기술 명세는 [`3-model/README.md`](../3-model/README.md)에 있다. 각자 자기 항목을 읽고 거기부터 시작한다.

## 분담표

| 팀원 | 담당 | 작성 파일 | 솔버 | 선행 조건 |
|---|---|---|---|---|
| **A** | 로버스트 · 완전정보 · 공용 하네스 · **MILP 코어** | `planners/robust.py` `planners/perfect.py` `core/` `run_all.py` | 직접 작성 | 없음 |
| **B** | FCFS  | `planners/fcfs.py` `tests/golden.py` | **불필요** | A의 1주차 |
| **C** | 결정론 nominal | `planners/nominal.py` | 코어 호출 | 조사는 지금 가능 |
| **D** | 확률계획 SAA | `planners/saa.py` `docs/` | 코어 호출 | 실증·문서는 지금 가능 |

**MILP를 처음부터 짜는 사람은 A 한 명이다.** nominal·SAA·로버스트는 제약이 전부 같고
목적함수만 다르므로, 제약은 `core/milp.py` 한 곳에만 둔다.
C·D는 시나리오를 만들어 그 코어에 넘기는 일을 한다.
덕분에 "누가 어떤 제약을 빠뜨렸나"를 따질 일도 없어진다.

B·C·D는 서로 독립이며, A의 1주차 산출물이 나오면 동시에 착수할 수 있다.

## 팀원 A — 모형 · 하네스

**1주차에 코드보다 인터페이스를 먼저 고정한다.** 이게 나머지 셋을 동시에 푼다.

- 인스턴스 스키마 확정 → C가 제원을 꽂을 수 있게 된다
- `plan()` 시그니처 + `core/recourse.py` → B·D가 각자 착수할 수 있게 된다
- 샘플 인스턴스 3개 커밋 → 셋의 테스트 픽스처

2주차부터 로버스트 모형, 3주차에 Γ 민감도와 완전정보.

`core/`는 A만 수정한다 (2단계 계산이 한 곳에만 있어야 한다). 2단계(시작 시각) 계산이 여기 한 곳에만 있어야 비교가 성립한다.

---

## 팀원 B — FCFS · 골든 테스트

**솔버가 필요 없다. 순수 Python 30줄이다.**

`plan()` 하나만 채운다. 도착 순으로 줄 세우고, 들어갈 수 있는 선석 중 가장 한가한 곳에 붙이고, 크레인은 받을 수 있는 최대로 준다. 시작 시각은 반환하지 않는다 — 그건 공용 코드가 한다.

골든 테스트도 맡는다. 손으로 푼 초소형 인스턴스(선석 1개·선박 3척 등)의 답을 박아두고, 공용 복구 규칙이 그 답을 내는지 확인한다. **"대기시간을 도착부터 세나 재개부터 세나" 같은 불일치가 1주차에 터지게** 하는 장치다.

## 팀원 C — nominal · 터미널 제원

**앞 절반은 코딩이 아니다. 조사다. 지금 바로 시작할 수 있다.**

| 항목 | 용도 |
|---|---|
| 터미널별 선석 수 · 안벽 길이 | 인스턴스의 `berths` |
| 터미널별 안벽크레인 수 | `cranes.total`, 선석당 상한 |
| 크레인 시간당 처리량 | `rate_tph` |
| 크레인 생산성 저하 계수 κ | 민감도 분석 대상 |

대상은 **부산신항 터미널 1개**다. 항만 전체가 아니다 — BAP는 원래 터미널 단위 문제이고, 운영사가 다른 터미널끼리는 선석을 공유하지 않는다. 선석 4~6개 규모가 적당하다. 너무 작으면 배정 자유도가 없어 방법 간 차이가 안 나고, 너무 크면 MILP가 안 풀린다. **제원이 공개된 터미널**로 고른다.

κ는 실측이 불가능하다. **값 하나가 아니라 범위**를 찾아온다.

뒤 절반은 nominal이다. 불확실성을 무시하고 명목 시나리오 하나로만 최적화한다.
MILP를 직접 짜지는 않는다 — A의 `core/milp.py`를 호출한다.

```python
return solve(build(inst, [nominal_scenario(inst)], "nominal"))
```

## 팀원 D — SAA · 실증 · 문서

**SAA는 nominal과 구조가 거의 같다.** 차이는 목적함수뿐이다.

```
nominal :  min  (명목 시나리오 1개의 비용)
SAA     :  min  (1/K) Σ_k (시나리오 k의 비용)
```

C와 같은 코어를 호출하고 인자만 바꾼다.

```python
return solve(build(inst, sample(inst, cfg["scenario"]["n_scenario_saa"]), "mean"))
```

모형 안에서 쓰는 시나리오와 평가용 시나리오는 **시드를 분리**한다.

나머지 절반은 지금 바로 할 수 있다.

- 기존 DiD 결과를 발표용 그림으로 (현재 ASCII 출력뿐이라 그림이 하나도 없다)
- 와일드 부트스트랩 추가 (클러스터 19개로 적어 t값이 낙관적일 수 있음)
- 제안서를 최종 보고서로 확장, 슬라이드 제작

문서가 밀리면 결과가 있어도 점수가 안 나온다.

## 공통 규칙

**① 1단계와 2단계를 섞지 않는다.**
`plan()`은 선석 배정·접안 순서·크레인 수만 반환한다. 시작 시각은 공용 코드가 계산한다.

**② 숫자는 `run_all.py` 출력에서만 나온다.**
각자 스크립트로 뽑은 수치는 보고서에 쓰지 않는다.

**③ 설정은 `config.yaml`에만 둔다.**
time limit, 시드, Γ를 자기 코드 안에 하드코딩하지 않는다.

**④ 실현 시나리오는 인스턴스와 같이 커밋한다.**
생성기가 한 줄만 바뀌어도 시드가 재현을 못 한다.

**⑤ 각자 브랜치에서 작업한다.** `main` 직접 푸시 금지.

**⑥ 막히면 혼자 2시간 넘기지 않는다.**

## 주차 계획

```
1주차  A  하네스 + 샘플 인스턴스 커밋        ← 나머지 셋을 푸는 열쇠
       B  골든 테스트 읽고 FCFS 착수
       C  터미널 제원·κ 조사
       D  DiD 결과 그림화 + 보고서 뼈대

2주차  A  로버스트 모형
       B  FCFS 완성, 골든 테스트 통과
       C  nominal MILP
       D  SAA

3주차  A  Γ 민감도 + 완전정보
       전원  격자 전체 실행
       D  와일드 부트스트랩, 실증 파트 작성

4주차  전원  에피소드 사례 연구, 표·그림 확정, 발표 준비
```

**1주차가 전부다.** 하네스가 안 나오면 셋이 동시에 논다.

## 위험과 대비

| 위험 | 대비 |
|---|---|
| 로버스트 모형이 안 끝남 | nominal + FCFS 비교만으로도 제출 가능한 형태 유지 |
| 한 묶음이 비어도 | FCFS 30줄, nominal·SAA는 코어 호출 몇 줄 — A가 대체 가능 |
| 도착 과정이 임의로 보임 | DiD 계수를 강도 함수로 변환하는 규칙을 `3-model/README.md`에 명시 |
| 완전정보를 하한이라 단정 | 2단계가 고정 규칙이므로 "그 규칙 하의 최선"으로 기술 |
| 터미널 제원을 못 구함 | 문헌 전형값으로 가정하고 민감도로 처리 |
| 2단계를 각자 다르게 품 | `core/recourse.py` 단일 파일, A만 수정 |
| 규격 벗어난 코드 | `validate_stage1()`이 자동으로 거부 |
