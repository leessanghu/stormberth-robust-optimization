# 2. 항만 활동 분석

태풍 전후로 항만이 실제로 멈추고 밀리는지 확인합니다.
제안서의 전제 — *"태풍 후 Vessel Bunching과 Backlog가 생긴다"* — 를 데이터로 검증하는 단계입니다.

---

## 데이터 — IMF PortWatch

전 세계 선박 9만 척의 AIS 신호를 집계한 **일별 항만활동** 데이터입니다. 무료, 가입 불필요.

```
기간   2019-01-01 ~ 2026-11-13   (2,874일, 결측 0)
항만   한국·일본·대만·중국 23개
지표   portcalls_container  일별 컨테이너선 기항 수   ← 주지표
       portcalls            전체 기항 수
       import / export      화물량 추정 (톤)
```

전체 데이터셋은 3.2GB라 `download_portwatch.py`가 **대상 항만만 필터**해 10MB로 받습니다.

> **할 수 있는 것**: 기항 수 증감, 폐쇄, 도착 집중(bunching), 화물량 회복,
> 그리고 **기항 1건당 작업량 분포**(일별 물동량 ÷ 기항수)
> **할 수 없는 것**: 선박 한 척을 추적하는 것 — 어느 배가 몇 시에 와서 언제 떠났는지는 없습니다

이 구분이 모형에 어떻게 연결되는지는 아래 **모형에 무엇을 공급하는가**를 보세요.

## 태풍 데이터가 어떻게 붙나

[`1-typhoon/`](../1-typhoon/)이 구한 노출시간이 여기로 들어옵니다. 과정은 간단합니다.

### 붙이는 방법 — 항만 이름과 날짜로 맞춥니다

1단계가 내놓는 파일은 이렇게 생겼습니다 (부산 2022년).

```
port  date        storm       h34
부산  2022-09-05  HINNAMNOR    6.0      <- 그날 34kt 바람 안에 6시간 있었다
부산  2022-09-06  HINNAMNOR    6.0
부산  2022-09-18  NANMADOL     6.0
부산  2022-09-19  NANMADOL    12.0
```

`panel_build.py`가 이걸 기항 데이터 옆에 갖다 붙입니다.

```
날짜          기항수   h34   태풍왔나   상대일
2022-09-03      23    0.0      0        -2
2022-09-04       3    0.0      0        -1
2022-09-05       0    6.0      1         0     <- 상륙일
2022-09-06      28    6.0      1        +1
2022-09-07      50    0.0      0        +2
2022-09-08      41    0.0      0        +3
```

**상대일**은 상륙일을 0으로 놓고 앞뒤로 센 날짜입니다. 이게 분석의 뼈대입니다.

### 노출시간을 두 번 씁니다

**㉠ 태풍이 왔냐 안 왔냐 (0/1)**

`h34`가 0보다 크면 "태풍 온 날"입니다. 그날이 **상륙일**이 되고, 거기서부터 상대일을 매깁니다.

```
log(1+기항수) = Σ 상대일별 계수 + 항만효과 + 날짜효과
```

**주 결과(상륙일 −83.7%)는 전부 여기서 나옵니다.** 이때는 몇 시간이었는지 안 보고,
0이냐 아니냐만 봅니다.

**㉡ 몇 시간이었냐**

태풍 하나당 노출시간을 다 더해서 약·중·강으로 나눕니다.

```
힌남노 = 6 + 6  = 12시간  -> 중
난마돌 = 6 + 12 = 18시간  -> 중
```

등급별로 따로 회귀를 돌린 게 **용량-반응**입니다.

| 등급 | 노출 합계 | 상륙일 | 이튿날 |
|---|---|---|---|
| 약 | 6–12h | −75.8% | +0.6% |
| 중 | 12–24h | −85.3% | −27.4% |
| 강 | 24–72h | −89.7% | **−74.5%** |

**"세기보다 지속시간"이 여기서 나옵니다.** ㉠은 태풍이 있었냐만 보고,
㉡이 얼마나 오래였냐를 봅니다.

### 아는 결함 하나

위 표를 자세히 보면 9월 11일이 이상합니다.

```
2022-09-11   상대일 = -7
```

힌남노(9/5)의 D+6인데, 난마돌(9/18)의 D−7로 덮였습니다.
**사후 관찰창이 21일인데 성수기엔 태풍이 2주 간격으로 와서 창이 겹칩니다.**
나중 태풍이 앞 태풍을 덮어씁니다.

166개 중 33개(20%)가 이렇습니다. 겹치지 않는 113개만 써도 상륙일 −83.4%로 결과는 같고,
반등은 오히려 +20.1%로 커집니다. 겹침이 신호를 희석시키고 있었다는 뜻입니다.

## 23개 항만 패널 (주 분석)

부산 1개만 보면 "9월이라 원래 그런 것 아니냐"에 답할 수 없어,
**19개 컨테이너항 × 2,874일 이중차분**으로 넓혔습니다.

```
log(1+기항수)_it = Σ_k β_k·1[상대일=k] + 항만FE_i + 날짜FE_t + ε_it
```

날짜FE가 "그날 세계가 조용했다"를, 항만FE가 "홍콩이 부산보다 크다"를 걷어냅니다.

```
상륙일     -83.7%  [-88.0, -77.9]
이튿날     -44.3%  [-57.4, -27.1]
사흘 뒤    +16.3%  [ +1.8, +32.7]   <- Vessel Bunching
```


### 이게 왜 작동하나 — 실제 하루로

2022-09-05 힌남노 상륙일, 19개 항만 실측입니다.

**① 항만FE — 각 항만을 "자기 평소"와 비교합니다.**

항만마다 크기가 다릅니다. 홍콩은 평소 35척, 인천은 6척이라 그냥 비교하면 안 됩니다.

| 항만 | 그날 | 평소 | 차이 |
|---|---|---|---|
| **부산** | 0척 | 33척 | **−3.50** |
| 상하이 | 0척 | 32척 | −3.48 |
| 인천 | 0척 | 6척 | −1.88 |
| 가오슝 | 16척 | 20척 | −0.16 |
| **홍콩** | 47척 | 35척 | **+0.31** |

**② 날짜FE — "그날 전체 분위기"를 뺍니다.**

그날 19개 항만 평균이 −0.84만큼 내려가 있었습니다 (힌남노가 한중을 동시에 때림).
이건 부산만의 효과가 아니라 그날 공통으로 깔린 것이라 빼줍니다.

```
부산의 자기 평소 대비 차이    −3.50
그날 전체의 평균 차이         −0.84   <- 뺀다
────────────────────────────────────
부산만의 태풍 효과            −2.66   -> 비율로 −93%
```

**왜 이게 "9월이라 그런 것 아니냐"를 막나.**
그날 홍콩은 **+0.31로 멀쩡**했습니다. 9월이라서, 또는 세계 해운이 쉬어서 부산이 멈춘 거라면
홍콩도 같이 내려갔어야 합니다. 안 내려갔습니다.
**안 맞은 항만이 그날의 기준선이 되고, 거기서 벗어난 만큼이 태풍 효과**입니다.

### 왜 log(1+기항수)인가

`log`를 씌우면 계수가 바로 %로 읽힙니다 (−2.66 -> `exp(−2.66)−1` = −93%).
항만 크기가 제각각이라 "몇 척 줄었나"보다 "몇 % 줄었나"가 비교 가능합니다.
`+1`은 0척인 날 때문입니다 — `log(0)`은 정의가 안 됩니다.

### 왜 날짜마다 계수를 따로 두나

"태풍 전 vs 후"로 뭉치지 않고 −7일부터 +21일까지 **하루에 계수 하나씩** 둡니다.
그래야 **모양**이 보입니다 — 언제 떨어지고, 언제 바닥이고, 언제 튀고, 언제 정상인지.
뭉쳤으면 "평균 −20%" 같은 밋밋한 숫자만 나왔을 겁니다.

그리고 **D−7~D−4가 0 근처**라는 게 중요합니다.
태풍 오기 전엔 아무 일도 없었다는 뜻이고, "다른 이유로 원래 떨어지던 중이 아니었다"는 증거입니다.

사전 추세(D-7~D-4)는 전부 비유의, 플라시보 20회는 전부 ±4% 안.
34kt 노출시간이 길수록 더 멈추는 용량-반응도 단조입니다.
전체 결과는 [`docs/findings.md`](../docs/findings.md)에 있습니다.

```bash
python 2-port/scripts/panel_build.py   # 패널 구축 (노출 파일 필요)
python 2-port/scripts/panel_did.py     # 이중차분
```

## 모형에 무엇을 공급하는가

이 프로젝트는 **최적화 모형과 알고리즘**이 결과물입니다. 데이터는 두 가지 일을 합니다.

**1) 전제를 증명합니다.** 태풍에 노출된 항만은 상륙일 기항이 −83.7% 떨어지고
사흘 뒤 +16.3%로 몰립니다 — 문제가 실재한다는 근거입니다.

> 주의: 부산 원자료의 "1.3~1.8배"와 DiD의 "+16%"는 기준이 다릅니다.
> 전자는 연 중앙값 대비, 후자는 D−7 대비이며 그날의 세계 공통 효과를 뺀 값입니다.
> **모형에는 보수적인 DiD 수치를 씁니다.** 1.8배로 잡으면 과대 설정입니다.

**2) 불확실성 집합을 실측으로 고정합니다.** 이게 차별점입니다.
기존 robust BAP 연구 대부분은 변동폭 Γ를 임의로 잡는데, 여기서는 관측값으로 잡습니다.

```
파라미터            출처              값
도착률 λ            PortWatch 실측    일평균 33척
폐쇄 지속 T_reopen   DiD 용량반응      약 6-12h / 중 12-24h / 강 24-72h
도착 집중 배수       DiD 실측          D+3에 +16% (컨테이너항 +20%)
기항당 작업량        PortWatch 실측    중앙 10,300톤, Q1-Q3 8,900-12,000
선석 수 B, 크레인 q̄  BPA 터미널 제원    공개 자료
처리시간 H_i        작업량 ÷ 생산성    위 분포 + 크레인 생산성 가정
크레인 저하 κ        문헌값 + 민감도    실측 불가 → 민감도 분석 대상
```

실측으로 확인한 중요한 사실 하나 — **태풍 재개 직후에도 기항당 작업량은 변하지 않습니다**
(평시 10,297톤 vs 재개 직후 9,952톤, 변동계수는 오히려 감소).
즉 태풍 충격은 **선박이 커지는 게 아니라 숫자가 몰리는 것**입니다.
불확실성을 도착 과정에만 두고 H_i 분포는 고정해도 된다는 근거가 됩니다.

## 파생변수 정의

기항 수만으로 병목을 재기 위해 만든 지표들입니다.

| 변수 | 정의 | 의미 |
|---|---|---|
| `baseline(t)` | 요일효과 제거 후 이벤트 전후 구간의 중앙값 | 평년 수준 |
| `ratio(t)` | 실제 / baseline | 상대 활동량 |
| `deficit(t)` | baseline − 실제 | 당일 미도착분 |
| `CD(t)` | Σ deficit | 누적 미도착 |
| 해소일수 | CD가 0 이하로 복귀한 날 | 회복 속도 |

### ⚠️ CD 해석 주의

**CD는 "항만에 밀려 있는 배"가 아니라 "오지 않은 배"입니다.**
PortWatch는 도착을 세지 대기열을 세지 않습니다. 따라서 CD는

- 배들이 **나중에 몰려오면** 떨어지고 → 적체
- 배들이 **아예 안 오면** 안 떨어집니다 → 결항·우회

후자는 스케줄링 알고리즘과 무관합니다. 또 **CD는 베이스라인에 매우 민감**합니다.
사후 구간을 베이스라인에 포함하면 기준이 부풀어 적체가 과대평가됩니다.

> 논문에 쓸 때는 베이스라인 없이 성립하는 숫자를 쓰세요 —
> "기항 0척인 날 5일, 전부 태풍일", "재개 직후 최대 58척(평년 33척)" 쪽이 반박하기 어렵습니다.

## 주요 결과

자세히는 [`docs/findings.md`](../docs/findings.md).

**패널 이중차분 (주 결과)** — 19개 컨테이너항 × 2,874일, 항만FE + 날짜FE

| 상대일 | 효과 | 95% CI |
|---|---|---|
| D−1 | −62.7% | [−69.1, −55.0] |
| **D0** | **−83.7%** | [−88.0, −77.9] |
| D+1 | −44.3% | [−57.4, −27.1] |
| **D+3** | **+16.3%** | [+1.8, +32.7] |
| D+4 | +13.9% | [+5.7, +22.6] |

사전 추세 D−7~D−4는 전부 비유의, 플라시보 20회는 ±4% 안, 강건성 7개 사양에서 D0 −74~−85% 유지.

**부산에 실제로 몇 척이 몰렸나 (원자료)**

멈춘 뒤 다시 열렸을 때 평소보다 몇 척이 더 들어왔는지입니다.
평년은 요일효과를 뺀 뒤 상륙 45~15일 전 중앙값으로 잡았습니다.

| 에피소드 | 평년 | 최저 | 최대 반등 | 배수 | 재개 후 3일 | 평소 3일 | **초과** |
|---|---|---|---|---|---|---|---|
| 2019 타파 | 30척 | **0척** | D+1에 58척 | **1.94배** | 145척 | 90척 | **+55척** |
| 2023 카눈 | 35척 | 0척 | D+2에 51척 | 1.46배 | 142척 | 105척 | +37척 |
| 2022 힌남노 | 32척 | 0척 | D+2에 50척 | 1.56배 | 126척 | 96척 | +30척 |
| 2021 오마이스+찬투 | 30척 | 1척 | D+5에 44척 | 1.46배 | 116척 | 90척 | +26척 |
| 2020 마이삭+하이선 | 33척 | 0척 | D+6에 40척 | 1.21배 | 111척 | 99척 | +12척 |

**5개 합쳐 160척이 평소를 넘겨 몰렸습니다.**

가장 극적인 건 2019 타파입니다 — 0척에서 다음 날 58척으로, 하루 만에 2배입니다.

```
D−1    3척   0.10배
D 0    0척   0.00배   <- 완전 정지
D+1   58척   1.94배   <- 바로 다음 날 2배
D+2   43척   1.44배
D+7   33척   1.10배   <- 일주일 만에 정상
```

**몰리는 날이 태풍마다 다릅니다** — D+1(타파), D+2(힌남노·카눈), D+5~6(오마이스·마이삭).
모형이 특정 날짜를 가정하면 안 되고, **불확실성으로 다뤄야 할 직접적 근거**입니다.

**연속 태풍은 몰림이 흩어집니다.** 2020년은 9/2에 멈추고 회복하려는 순간
9/6에 하이선이 또 와서 다시 0척이 됩니다. 반등이 약한 대신 **정체가 길어집니다**.
최악 시나리오는 여기입니다.

> 위 배수(1.2~1.9배)는 **연 중앙값 대비**입니다.
> 세계 공통 효과를 뺀 DiD 기준으로는 +16% 수준이고, **모형에는 보수적인 DiD 값을 씁니다.**

재현: `python 2-port/scripts/busan_surge.py`

베이스라인 가정이 전혀 필요 없는, 가장 단순한 증거입니다.

## 울산은 왜 빠졌나

울산항만공사 선석배정현황으로 체류시간을 구하려 했으나 **출항일자 컬럼이 없고**,
`접안예정일자`마저 실제 접안이 아닌 *예정일*이라 시각 정보가 전혀 없었습니다.
울산은 유조선 중심이라 안벽크레인이 없어 QC 검증에도 쓸 수 없습니다.
데이터·스크립트는 내렸고, 커밋 이력에만 남아 있습니다.

**다만 거기서 나온 관찰은 패널 분석에서 검증됐습니다.** 울산에서는 접안 중단이
재현됐는데 backlog는 재현되지 않았고, 이게 *"Vessel Bunching은 컨테이너항 고유 현상"*
이라는 가설을 낳았습니다. 19개 항만을 탱커 비중으로 갈라 보니:

| 유형 | 상륙일 | 최대반등 |
|---|---|---|
| 탱커비중 낮은 절반 | −84.2% | **+19.6%** (D+3) |
| 탱커비중 높은 절반 | −81.5% | +13.0% (D+3) |

**정지는 둘 다 같은데 반등만 컨테이너항이 1.5배입니다.**
울산 결과가 데이터 결함이 아니라 실제 현상 차이였다는 뜻이고,
제안서가 왜 컨테이너항과 크레인을 다루는지를 뒷받침합니다.
