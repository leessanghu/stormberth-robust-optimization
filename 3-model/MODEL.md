# 모형 정의 — 제약 전체

네 방법(FCFS · nominal · SAA · 로버스트 · 완전정보)이 **무엇을 공유하고 무엇이 다른지**를
한 곳에 모은 문서입니다. `core/milp.py`를 쓸 때 이걸 보고 씁니다.

> **솔버**: `pulp` 4.2 에는 CBC 가 더 이상 안 들어 있습니다. 대신 **`scipy.optimize.milp`**
> (HiGHS 백엔드)를 씁니다. scipy 가 이미 깔려 있으므로 추가 설치가 필요 없습니다.

> **핵심**: 제약은 전부 같습니다. 다른 건 **목적함수와 시나리오**뿐입니다.
> 그래서 제약을 `core/milp.py` 한 곳에만 둡니다.

---

## 기호

### 집합

```
V     선박 집합            i, j ∈ V
B     선석 집합            b ∈ B
K     크레인 대수 후보      k ∈ {1, …, Q}
T     시간 구간            t ∈ {0, …, |T|−1},  구간 길이 Δ
S     시나리오 집합         s ∈ S
```

### 파라미터

| 기호 | 뜻 | 인스턴스 필드 |
|---|---|---|
| `aᵢˢ` | 시나리오 s에서 선박 i의 도착 시각 | `vessels[i].arrival_h` |
| `wᵢˢ` | 선박 i의 작업량 (톤) | `vessels[i].workload_t` |
| `Lᵢ` | 선박 i의 길이 (m) | `vessels[i].loa_m` |
| `q̲ᵢ, q̄ᵢ` | 선박 i가 받을 수 있는 크레인 하·상한 | `q_min`, `q_max` |
| `ℓ_b` | 선석 b의 안벽 길이 | `berths[b].length_m` |
| `Q̄_b` | 선석 b에 동시에 붙일 수 있는 크레인 상한 | `berths[b].q_max` |
| `Q` | 터미널 전체 크레인 수 | `cranes.total` |
| `r` | 크레인 1기 시간당 처리량 (t/h) | `cranes.rate_tph` |
| `t₀` | 항만 재개 시각 | `recovery.t_reopen_h` |
| `κ` | 재개 직후 크레인 효율 (0<κ≤1) | `recovery.kappa` |
| `Hor` | 계획 지평 | `horizon_h` |
| `M` | 충분히 큰 수 (big-M) | `Hor` 정도 |

### 변수

**1단계 — 시나리오와 무관하게 하나로 확정 (here-and-now)**

```
x_ib ∈ {0,1}     선박 i를 선석 b에 배정
z_ij ∈ {0,1}     같은 선석에서 i가 j보다 먼저        (i < j)
u_ik ∈ {0,1}     선박 i에 크레인 k대 배정            (정확히 하나만 1)
qᵢ   ∈ ℤ₊        선박 i의 크레인 수 = Σ_k k·u_ik
```

**2단계 — 시나리오마다 따로 (wait-and-see)**

```
Sᵢˢ ≥ 0          작업 시작 시각
Dᵢˢ ≥ 0          작업 종료(출항) 시각
Wᵢˢ ≥ 0          대기 시간
σᵢₜˢ ∈ {0,1}     선박 i가 구간 t에 작업 중
```

## 공통 제약 — 모든 MILP 방법이 동일

### (C1) 배정 유일성

선박 하나는 정확히 한 선석에 붙는다.

```
Σ_b x_ib = 1                                    ∀ i ∈ V
```

### (C2) 선석 길이

배가 선석보다 길면 못 들어간다. **전처리로 변수를 고정**한다 (제약으로 안 써도 됨).

```
x_ib = 0                                        ∀ i, b  such that  Lᵢ > ℓ_b
```

### (C3) 크레인 대수 선택

```
Σ_k u_ik = 1                                    ∀ i
qᵢ = Σ_k k · u_ik                               ∀ i
q̲ᵢ ≤ qᵢ ≤ q̄ᵢ                                   ∀ i
qᵢ ≤ Σ_b Q̄_b · x_ib                             ∀ i        (붙는 선석의 상한)
```

> **왜 `u_ik`를 쓰나.** 처리시간이 `wᵢ/(r·κ·qᵢ)`라 `qᵢ`가 **분모**에 있습니다.
> 그대로 두면 비선형입니다. 크레인 대수마다 이진변수를 두면 계수가 상수가 되어 **선형**이 됩니다.
> 이게 이 모형에서 가장 중요한 선형화 기법입니다.

### (C4) 처리시간과 종료 시각

```
Hᵢˢ = Σ_k ( wᵢˢ / (r · κ · k) ) · u_ik          ∀ i, s      ← 계수가 상수, 선형
Dᵢˢ = Sᵢˢ + Hᵢˢ                                 ∀ i, s
```

### (C5) 시작 시각 하한

배가 와야 하고, 항만이 열려야 시작한다.

```
Sᵢˢ ≥ aᵢˢ                                       ∀ i, s
Sᵢˢ ≥ t₀                                        ∀ i, s
```

### (C6) 같은 선석 비중첩 (disjunctive)

같은 선석에 붙은 두 배는 시간이 겹치면 안 된다.

```
Sⱼˢ ≥ Dᵢˢ − M·(1 − z_ij) − M·(2 − x_ib − x_jb)       ∀ i<j, ∀ b, ∀ s
Sᵢˢ ≥ Dⱼˢ − M·z_ij       − M·(2 − x_ib − x_jb)       ∀ i<j, ∀ b, ∀ s
```

읽는 법: `i, j`가 **둘 다 선석 b에** 있고(`x_ib = x_jb = 1`) `z_ij = 1`이면
첫 줄이 `Sⱼ ≥ Dᵢ`로 살아난다. 아니면 big-M이 제약을 풀어준다.

> `z_ij`는 **1단계 변수**입니다. 순서를 미리 확정한다는 뜻이고,
> 시나리오가 바뀌어도 순서는 그대로 갑니다. 이게 2단계 로버스트의 핵심입니다.

### (C7) 크레인 총량

어느 시점에도 쓰는 크레인이 전체를 넘을 수 없다.

```
Σ_i Σ_k k · v_ikt ≤ Q                           ∀ t, s
```

`v_iktˢ = u_ik · σᵢₜˢ` 는 이진곱이라 그대로 못 쓴다. 표준 선형화:

```
v_ikt ≤ u_ik
v_ikt ≤ σᵢₜˢ
v_ikt ≥ u_ik + σᵢₜˢ − 1
v_ikt ≥ 0
```

### (C8) 작업 구간 연결 (σ ↔ S, D)

`σᵢₜ`가 실제 작업 구간과 맞아야 한다.

```
Σ_t σᵢₜˢ ≥ Hᵢˢ / Δ                              ∀ i, s      (구간 수 하한)
t·Δ      ≥ Sᵢˢ − M·(1 − σᵢₜˢ)                   ∀ i, t, s   (시작 이후)
(t+1)·Δ  ≤ Dᵢˢ + M·(1 − σᵢₜˢ)                   ∀ i, t, s   (종료 이전)
```

> **이 꼴 그대로 쓰면 실행불가입니다 (실측).** 위 두 줄은 "구간이 `[Sᵢ, Dᵢ]`에
> **완전히 포함**될 때만 `σᵢₜ`를 켤 수 있다"는 뜻입니다. 그런데 `Hᵢ`가 `Δ`의 배수가
> 아니면 창 안에 들어오는 **온전한** 구간 수가 `Hᵢ/Δ`보다 적어, 첫 줄
> `Σ_t σᵢₜ ≥ Hᵢ/Δ`와 충돌합니다. HiGHS가 `infeasible`을 돌려줍니다.
>
> **수정 (겹침 기준)** — 구간이 창과 **겹치기만** 하면 켤 수 있게 풉니다.
>
> ```
> t·Δ + Δ  ≥ Sᵢˢ − M·(1 − σᵢₜˢ)                 ∀ i, t, s
> t·Δ      ≤ Dᵢˢ + M·(1 − σᵢₜˢ)                 ∀ i, t, s
> ```
>
> 겹침 기준은 크레인 점유를 **과대계상**하므로 (C7) 방향으로 보수적입니다 — 안전한 쪽입니다.
> 대신 모형 목적값이 recourse 평가값보다 커질 수 있습니다.
> `Sᵢ ∈ Δℤ`로 격자에 맞추는 것도 되지만 더 보수적입니다.

### (C9) 대기 시간

```
Wᵢˢ = Sᵢˢ − aᵢˢ ≥ 0                             ∀ i, s
```

### (C10) 계획 지평

```
Dᵢˢ ≤ Hor                                       ∀ i, s
```

> 지평 안에 다 못 넣으면 실행불가가 됩니다. 인스턴스를 만들 때 ρ ≤ 0.9로 두는 이유입니다.
> 빡빡하게 가려면 이걸 **소프트 제약**(초과분에 벌점)으로 바꾸는 게 안전합니다.

## 여기까지가 공통. 이제 방법별로 갈립니다

### 목적함수의 공통 꼴

시나리오 s에서의 비용:

```
f(s) = Σ_i (Dᵢˢ − aᵢˢ)        총 재항시간
```

(대기만 보려면 `Σ_i Wᵢˢ`로 바꿉니다. **한 번 정하면 모든 방법이 같은 걸 씁니다.**)

---

## 방법별 차이 — 이 표가 전부입니다

| 방법 | 시나리오 집합 S | 목적함수 | 추가 제약 |
|---|---|---|---|
| **nominal** | 명목값 1개 | `min f(s₀)` | 없음 |
| **SAA** | 무작위 K개 | `min (1/K) Σ_s f(s)` | 없음 |
| **로버스트** | 불확실성 집합 꼭짓점 | `min max_s f(s)` | epigraph |
| **완전정보** | 실현값 1개 (시나리오마다 따로) | `min f(s_real)` | 없음 |

### nominal

```
S = { s₀ }         aᵢ, wᵢ = 인스턴스에 적힌 값 그대로
목적: min f(s₀)
```

### SAA

```
S = { s₁, …, s_K }   K = config.yaml 의 n_scenario_saa
목적: min (1/K) Σ_s f(s)
```

**1단계 변수(`x, z, u`)는 시나리오 전체가 공유**하고, 2단계 변수만 시나리오마다 복제합니다.
그래서 모형 크기가 K배로 커집니다.

> 평가용 시나리오와 **시드를 분리**하세요. 같은 걸 쓰면 자기 시험지를 미리 본 셈입니다.

### 로버스트 — 최악을 epigraph로

`min max`는 그대로 못 풉니다. 보조변수 `θ`를 둡니다.

```
min θ
s.t.  θ ≥ f(s)                                  ∀ s ∈ S
      (C1)~(C10)                                ∀ s ∈ S
```

**불확실성 집합** (Bertsimas–Sim 예산):

```
ãᵢ = aᵢ + ξᵢ · δᵢ,     ξᵢ ∈ [0,1],     Σᵢ ξᵢ ≤ Γ
```

`δᵢ`는 `config.yaml`의 `arrival_jitter_h`, `Γ`는 `gamma`입니다.

꼭짓점은 "`ξᵢ` 중 최대 Γ개가 1, 나머지 0"인 0/1 벡터들입니다.
선박 25척에 Γ=3이면 `C(25,3) = 2,300`개 — **전부 넣으면 모형이 터집니다.**

**이번 학기 방식**: 꼭짓점을 **표본으로 뽑아** 쓰고, 보고서에 **근사 Γ-로버스트**라고 명시합니다.
정석인 행 생성(row generation)은 향후 과제로 둡니다.

### 완전정보

실현 시나리오 **하나하나에 대해 따로** 풉니다. 도착이 이미 알려졌으므로 불확실성이 없습니다.
모형은 nominal과 같고 입력값만 실현값입니다. 20개 실현의 평균을 보고합니다.

## FCFS — MILP가 아닙니다

최적화를 하지 않습니다. 규칙으로 1단계를 만듭니다.

```
1. 배를 aᵢ 오름차순 정렬
2. 앞에서부터: Lᵢ ≤ ℓ_b 인 선석 중 누적 작업량이 가장 작은 곳에 붙임
3. qᵢ = min(q̄ᵢ, Q̄_b)
```

다만 **(C1)(C2)(C3)은 반드시 만족해야 합니다.** `validate_stage1()`이 이걸 검사합니다.

```
모든 배가 정확히 한 번씩 배정됐나      <- C1
배가 선석에 물리적으로 들어가나         <- C2
크레인 수가 범위 안인가                <- C3
```

(C4)~(C10)은 2단계 제약이라 FCFS가 신경 쓸 필요가 없습니다. `core/recourse.py`가 처리합니다.

## 꼭 기억할 것 — 모형의 `Sᵢ`는 평가에 쓰이지 않습니다

MILP가 `Sᵢ`를 계산하더라도, **반환하는 것은 `x, z, u`(순서와 크레인 수)뿐**입니다.
실제 시작 시각은 `core/recourse.py`가 **모든 방법에 똑같은 규칙으로** 다시 계산합니다.

왜 이렇게 하나:

```
각자 2단계를 풀면   ->  "배정이 좋아서 이겼나, 시간 계산이 달라서 이겼나" 구분 불가
공용 규칙을 쓰면    ->  차이의 원인이 1단계 하나로 좁혀짐
```

그래서 **모형 목적값은 평가값의 하한**입니다. 규칙이 최적이 아니기 때문입니다.
보고서의 비교는 **평가값으로만** 합니다. 모형 목적값은 진단용으로만 씁니다.

```
gap = 평가값 − 모형 목적값        크면 규칙이 느슨하다는 신호
```

## 모형 크기 가늠

선박 25척, 선석 4개, 크레인 12기, 구간 72개(Δ=1h), 시나리오 1개 기준:

| 변수 | 개수 |
|---|---|
| `x_ib` | 25 × 4 = 100 |
| `z_ij` | 25×24/2 = 300 |
| `u_ik` | 25 × 12 = 300 |
| `σᵢₜ` | 25 × 72 = 1,800 |
| `v_ikt` | 25 × 12 × 72 = 21,600 |

**`v_ikt`가 압도적입니다.** 줄이는 방법:

- Δ를 2~3시간으로 키운다 (구간 수 감소)
- `k`를 전수가 아니라 쓸 법한 값만 (예: 1,2,3,4) 둔다
- 선박 i가 절대 작업할 수 없는 구간 t는 사전에 제거한다

막히면 Δ부터 키우세요. 가장 효과가 큽니다.
