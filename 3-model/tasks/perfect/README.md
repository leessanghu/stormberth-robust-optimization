# perfect — 완전정보 (기준선)

## 내가 할 일

**누가 언제 올지 미리 다 알고** 푼 답을 구합니다.

현실에서는 불가능합니다. 미래를 아는 셈이니까요.
그래서 이건 쓰려고 만드는 게 아니라 **기준선**으로 만듭니다.

## 왜 필요한가

> "최대로 잘하면 어디까지 갈 수 있나?"

이걸 모르면 로버스트가 900시간을 냈을 때 그게 잘한 건지 알 수가 없습니다.
완전정보가 850시간이면 거의 최선이고, 500시간이면 아직 한참 멀었다는 뜻입니다.

**로버스트와의 격차가 "미래를 몰라서 치르는 비용"** 입니다.
확률계획에서는 이걸 **EVPI**라고 부릅니다.

## 어떻게 푸나

실현 시나리오마다 따로 풉니다. 도착 시각이 이미 알려진 값이므로 **불확실성이 없습니다.**
즉 nominal과 같은 모형인데, 명목값 대신 **그 시나리오의 실제값**을 넣습니다.

```python
# 시나리오 20개 각각에 대해 최적 1단계를 구하고, 그 평균을 보고
```

## 꼭 지킬 것 — "절대 하한"이라고 쓰면 안 됩니다

우리 2단계는 **고정된 규칙**(`core/recourse.py`)입니다. 최적화가 아닙니다.

그래서 여기서 말하는 완전정보는
*"실현값을 다 알고 1단계를 최적으로 골랐을 때, **그 규칙 하의** 최선"* 입니다.
규칙 자체가 최적이 아니므로 진짜 최적해는 이보다 더 낮을 수 있습니다.

보고서에 "이론적 하한"이라고 쓰면 지적당합니다. **"그 규칙 하의 최선"** 으로 쓰세요.

## 자가 점검에 쓰입니다

`run_all.py`가 끝나면 이 순서를 자동으로 확인합니다.

```
완전정보  ≤  SAA  ≤  nominal        (평균 기준)
```

**이건 정리입니다.** 경험칙이 아니라 수학적으로 항상 참입니다.
깨지면 어딘가 코드가 틀린 겁니다. 돌릴 때마다 보고 넘어가세요.
