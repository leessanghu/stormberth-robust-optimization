# saa — 표본평균근사 (RP)

> 공통 안내 → [`../../START.md`](../../START.md)

## 내가 할 일

**불확실성의 분포를 안다고 보고**, 거기서 시나리오 K개를 뽑아 **평균**을 최소화합니다.

## 이게 왜 중요한가

로버스트와 **정면으로 대비되는** 방법입니다. 둘 다 불확실성을 다루지만 가정이 다릅니다.

| | 가정 | 최소화 대상 |
|---|---|---|
| 로버스트 | "최악이 이 범위" (집합) | **최댓값** |
| SAA | "분포가 이럴 것" (확률) | **평균** |

같은 불확실성을 **어떻게 모형화하느냐**가 결과를 가른다는 걸 보여주는 자리입니다.
이 둘을 나란히 놓지 않으면 "로버스트가 좋다/나쁘다"를 말할 근거가 없습니다.

> 확률계획 용어로 이 값을 **RP** (recourse problem) 라고 합니다.

## 정리 — 내 숫자가 여기 끼어야 합니다

```
완전정보(WS)  <=  SAA(RP)  <=  nominal(EEV)
```

Birge & Louveaux 의 정리입니다. `run_all.py` 가 자동 점검합니다. **깨지면 버그입니다.**
내 자리는 완전정보와 nominal 사이이고, 이 부등식이 성립하는지가 하네스 전체의 검산입니다.

> 주의: `nominal <= FCFS` 는 **정리가 아닙니다.** 깨져도 버그가 아닙니다.

## 함정 둘 — 둘 다 조용히 틀립니다

### ① CV 를 로그정규 sigma 에 그대로 넣기

```python
random.lognormvariate(0, CV)        # ← 틀렸습니다
```

`sigma` 와 변동계수는 다른 값입니다. 변환해야 합니다.

```python
sigma = math.sqrt(math.log(1 + CV**2))
x = random.lognormvariate(0, sigma) * math.exp(-sigma**2 / 2)   # 평균 보존
```

CV 0.2 에서는 티가 안 나다가 CV 1.8 에서 **작업량 평균이 5배**가 됩니다.
그러면 모든 방법의 숫자가 같이 부풀어서 "혼잡할수록 최적화가 유리하다" 같은
가짜 결론이 나옵니다.

### ② 계획 표본과 평가 실현의 시드가 겹치기

SAA 가 계획에 쓴 시나리오가 평가 실현에 섞이면 **자기 답안지를 보고 푸는 것**입니다.
SAA 만 부당하게 좋아지고, 그 상태로는 아무것도 주장할 수 없습니다.
`cfg["run"]["seed"]` 에서 충분히 떨어뜨리세요.

## K 를 몇으로 할 것인가 — 이게 내 분석거리입니다

`config.yaml` 의 `n_scenario_saa` 입니다. K 를 키우면 참 평균에 가까워지지만 느려집니다.
**K 를 바꿔가며 성능과 시간을 재서 수렴 곡선을 그리는 게 내 보고서 절의 핵심입니다.**
K = 5 / 10 / 20 / 40 정도면 충분합니다.
