# nominal — 결정론 최적화

> 공통 안내를 먼저 읽으세요 → [`../_COMMON.md`](../_COMMON.md)

## 내가 할 일

**배가 적힌 시각에 정확히 올 거라 믿고** 가장 좋은 배정을 찾습니다.
불확실성은 전혀 고려하지 않습니다.

## 이게 왜 필요한가

우리 연구의 **핵심 비교 대상**입니다.

로버스트는 "운 나쁜 경우까지 대비한" 배정이고, nominal은 "예정대로 될 거라 믿은" 배정입니다.
둘을 **같은 실제 상황에 던져놓고** 비교하면, *"불확실성을 고려한 게 이득이었나"* 에 답이 됩니다.

그게 이 연구가 증명하려는 전부입니다. 이 자리가 비면 로버스트가 좋다는 걸 말할 방법이 없습니다.

> 확률계획 용어로 이 해를 실제 상황에서 평가한 값을 **EEV**라고 부릅니다.

## MILP를 처음부터 짜지 않습니다

제약(어떤 배가 어느 선석에, 겹치면 안 되고, 크레인 총량 넘으면 안 되고…)은
**모든 방법이 똑같습니다.** 그래서 A가 `core/milp.py`에 한 번만 씁니다.

내가 하는 건 **"시나리오 하나(명목값)를 넣고 풀어달라"** 고 부르는 것입니다.

```python
from core.milp import build, solve, nominal_scenario

def plan(inst, cfg):
    sc = nominal_scenario(inst)          # 인스턴스에 적힌 값 그대로
    model = build(inst, [sc], "nominal")
    return solve(model, cfg)
```

**A의 `core/milp.py`가 나오기 전까지는 손댈 수 없습니다.** 1주차에 나옵니다.
그동안은 아래 "기다리는 동안" 쪽을 하세요.

## 기다리는 동안 — 터미널 제원 조사

지금 당장 할 수 있고, 없으면 인스턴스를 못 만듭니다.

**대상: 부산신항 터미널 1개** (PNC · PNIT · HJNC · BNCT · BCT 중 **제원이 공개된 곳**)

| 찾을 것 | 어디에 쓰이나 |
|---|---|
| 선석 수와 안벽 길이 | `inst["berths"]` |
| 안벽크레인(QC) 수 | `inst["cranes"]["total"]` |
| 크레인 시간당 처리량 | `rate_tph` (지금은 390t/h로 가정 중) |
| 태풍 직후 생산성 저하 κ | `recovery.kappa` (지금 0.75 가정) |

**선석 4~6개 규모가 적당합니다.** 너무 작으면 배정할 게 없어 방법 간 차이가 안 나고,
너무 크면 MILP가 안 풀립니다.

**κ는 값 하나가 아니라 범위를 찾아오세요.** 실측이 불가능해서 민감도 분석 대상입니다.

> 항만 전체가 아니라 터미널 하나인 이유: 선석·크레인은 터미널 안에서만 공유됩니다.
> 운영사가 다른 터미널끼리는 선석을 돌려쓰지 않습니다.
